# Windows 免点击语音唤醒设计

状态：设计、实施计划及 Windows 本地引擎替代方案已获用户批准，正在实现和验证。日期：2026-10-08。

## 已批准的引擎调整

以 Windows System.Speech 中文固定语法引擎替代下面最初的 sherpa-onnx 候选，不下载模型权重、不安装 sherpa-onnx/numpy。Python sounddevice 仍独占采集流，将 PCM 通过本机管道送入 Windows 引擎；C# 有界流适配保留最近两秒缓冲以满足 SAPI 的定位和完整读取要求，音频不写盘、不上传。识别引擎不自行打开第二个麦克风。其余隐私、结束、超时和免点击目标不变。原模型目录配置仅为向后兼容保留，本轮不使用。

## 已确认目标与边界

启动 Yu 后自动等待“嘿，宇”；唤醒后直接对话，句尾自动提交，说“结束”后再次等待唤醒。无需打开网页或点击开始语音。首次需要在 Windows 允许桌面应用访问麦克风，此权限无法绕过。

本阶段不做托盘、开机自启、EXE 打包、手机、跨端同步、歌曲搜索或歌单播放。不更换已经可用的阿里云北京实时识别，也不自动切换供应商。付费音频连接只在唤醒后的对话期间存在。

## 方案选择

推荐：Python 本地语音进程，使用 sherpa-onnx 中文关键词检测和 sounddevice 采集麦克风，复用现有本机 API。

网页检测不能满足关闭网页仍可唤醒的目标；持续云端识别再匹配唤醒词会持续上传环境声音和产生费用，均不采用。Windows 原生语音识别可作为后续候选，但首阶段不同时开发第二个检测引擎。

项目已确认没有 sherpa-onnx、sounddevice 或 numpy。本阶段需要新增可选依赖和独立模型目录，不修改既有语音依赖的默认行为。关键词模型优先验证官方中文 Zipformer KWS，模型下载大小、许可证、完整性和实际误唤醒率必须在安装前核对；不承诺未经测量的准确率。

## 模块与数据流

1. 本地采集模块：独占一个输入流，输出单声道 16 kHz PCM；设备不支持时明确提示，不偷偷换采样率。回调只送有界内存队列，不执行网络或动作。
2. 唤醒模块：只在待唤醒状态解码本地音频；默认关键词“嘿，宇”，阈值可配置。音频不保存到磁盘、不上传。清理检测缓存和冷却时间防止一次唤醒触发多次连接。
3. 会话协调模块：唤醒后连接既有 `/api/voice/live`，等待 ready，再传音频；带上该本机服务要求的 Origin，不放宽现有来源检查。API Key 仍由服务读取，语音进程不通过 HTTP 或日志取回 Key。
4. 指令模块：partial 只展示；final 按句子 ID 去重、串行调用 `/api/chat`，复用原权限和审计。保留有限轮次 history 支持连续对话；不绕过 Safety Kernel。
5. 本地反馈模块：唤醒提示音和 Windows 本地朗读，不新增付费 TTS。朗读期间暂停上传、丢弃采集帧，避免回复变成命令；首阶段不支持边朗读边打断。结束朗读后短暂冷却并恢复对话监听。
6. 启动管理：单一启动入口管理本机 API 和语音进程的生命周期。重复启动不得产生多个麦克风监听器。Ctrl+C 释放输入流、关闭连接，并只停止本次启动拥有的子进程，不终止其他 Yu 实例或其他应用。

网页仍可访问；首阶段本地语音的状态、字幕和回复显示在运行窗口，不承诺自动同步进已有网页聊天。既有网页手动语音保留兼容，两种入口互斥；另一入口正在对话时，本地唤醒提示忙，不抢占会话。

## 状态和错误

启动检查 → 待唤醒 → 连接识别 → 对话监听 ↔ 执行动作/朗读 → 待唤醒。

- 唤醒后播放短提示音，提示音期间音频不上传；用户听到提示后说指令。首阶段不保证“嘿，宇打开微信”完全不停顿时不会截掉指令。
- “结束”“结束语音”“停止监听”“OK，结束”仅在整句结束命令时关闭识别连接，取消尚未执行的队列，回到待唤醒；不把“结束任务”等普通句子当结束指令。
- 默认连续 30 秒没有用户语音即返回待唤醒；单次会话最多 10 分钟。动作执行和朗读期间不计入闲置超时。
- 断网、Key 无效、额度不足、队列溢出：关闭本次连接、取消未执行指令、回到待唤醒并提示原因，不重发旧指令、不自动重连付费服务。
- 麦克风断开或模型缺失：停止监听并明确显示错误，不能显示“正在待唤醒”。模型缺失时提示安装命令，不自动大量下载或更改旧配置。
- 已开始执行的本机动作不能因结束命令回滚；保留真实回执。动作业务失败停止待执行队列并提示，但允许用户在同一会话提出新指令。
- 待唤醒仅监听关键词，并不代表用户身份认证；敏感操作依然必须由现有权限机制阻止或确认。

## 配置与隐私

默认关键词、模型目录、麦克风设备、阈值、闲置时限放在专用配置中，不混入应用启动路径。Key 仍保存在被 Git 忽略的本机 `.env`，禁止打印。终端明确显示“本地待唤醒”或“云端对话”，说明待唤醒时也在使用麦克风。保留 Ctrl+C 作为立即停止监听的明确入口。

模型加载、采集、唤醒、会话控制分别拆分，避免超大型文件。复用现有实时 ASR 协议和应用执行模块，只做必要改动。

## 验证和验收

自动测试：未唤醒不建立云端连接、不提交聊天；一次唤醒只连接一次；ready 前不上传；final 重复不重复执行；结束和闲置返回待唤醒；朗读期间不提交回声；网络/采集异常资源释放；多次启动和网页入口互斥。

真人验收：不打开网页、不点击按钮，启动后说“嘿，宇”，收到反馈，再说“打开微信”，已有微信窗口恢复且无新增实例；说“结束”后云端连接关闭，再次唤醒仍可用。另测音乐干扰、普通对话误唤醒、耳机和扬声器环境。将测量结果记录下来，不能用单元测试代替实际麦克风验收。

交付顺序：本地采集与唤醒 → 接现有云端对话及动作 → 本地回复和结束回待唤醒 → 生命周期与真人验证。随后才考虑替换本地 ASR、完善歌曲能力和 EXE。
